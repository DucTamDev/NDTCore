# POS Order Panel Layout Redesign + DeliveryAddress Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Refactor `PosOrderPanel.vue` into 3 fixed vertical zones (Header / scrollable Cart / always-visible Checkout) and add full-stack support for a `DeliveryAddress` field on orders.

**Architecture:** Pure layout/CSS refactor of an existing Vue component (no new components, no logic changes to existing functions) plus a standard CQRS field addition on the BE Order module (entity → EF config → migration → create flow → read flow) and a matching FE store/DTO addition.

**Tech Stack:** Vue 3 (Composition API) + TypeScript + Vuetify 3 + Pinia (FE); .NET 8 + EF Core 8 + MediatR + FluentValidation (BE).

## Global Constraints

- BE: every `class`/`interface`/`method`/`property` (including `private`) needs bilingual VN/EN XML doc — see existing patterns in the files being edited.
- FE: TypeScript strict, no `any`.
- Explanations to the user in Vietnamese; code, identifiers, file names in English.
- No comments explaining WHAT; only WHY when non-obvious.
- Don't add abstractions/features beyond what's specified (no new store actions for quick-cash, no new child component for checkout).
- Commit message format: `<type>: <short description>` (`feat`, `fix`, `refactor`, `docs`, `chore`, `test`).
- Never commit EF migration files in the same commit as the entity/config code that produced them — migrations are committed separately (project git-workflow rule).
- Before any BE commit: `cd NDTCore.BE/src && dotnet build NDTCore.sln` must succeed.
- Before any FE commit: `cd NDTCore.FE && npm run type-check` must succeed.
- This codebase has no unit test projects for the Order module or the pos FE module — verification is via the build/type-check commands above plus the manual checks described per task, not via new test suites (don't introduce a test framework as part of this work).
